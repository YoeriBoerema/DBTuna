# Security

Passwords live exclusively in VS Code SecretStorage. Host, port, database, username, TLS preference and display name are stored in globalState. Updating a profile requires re-entering the password. Removing a profile deletes its secret. Connection strings and SQL are not logged by application code. Exported plans may include query text and sensitive native attributes; review the chosen export destination.

Use a least-privilege role. EXPLAIN without ANALYZE does planning, but PostgreSQL may evaluate functions during planning. SQL classification and read-only transactions reduce risk; they are not an unconditional execution sandbox. Live access requires a trusted workspace. No standalone user SQL is submitted to generate results.

Webview scripts are bundled locally and protected by a nonce CSP. External scripts and network access are disallowed. Inline styles are permitted for React Flow's dynamic positioning. React escapes operator names, predicates and metadata. Local resource access is limited to dist. Incoming messages must contain exactly one known type and no payload.

No telemetry or standalone backend is implemented. Optional AI Assistance uploads the chosen query and plan to OpenAI only on explicit request. Large imports are rejected before reading by the extension and before normalization by the core. Imported graphs are validated before layout.

INSERT support requests a plan only: the host still prepends EXPLAIN (FORMAT JSON, VERBOSE TRUE, COSTS TRUE), never enables ANALYZE and retains BEGIN READ ONLY, statement timeout and ROLLBACK. Only the main statement may INSERT; data-modifying CTEs remain rejected. Batches are split into independent validated statements; an unsplit multi-statement string never reaches the collector. ON CONFLICT actions are part of that estimated INSERT plan. Target table row counts were verified unchanged in disposable PostgreSQL integration tests. Ordinary expression calls such as COALESCE are accepted; standalone CALL statements remain rejected. See [PostgreSQL EXPLAIN documentation](https://www.postgresql.org/docs/18/sql-explain.html).

Batch planning retains successes across query failures. Cancellation closes the active client and skips remaining statements. Each query gets its own read-only transaction, timeout and rollback. Imports restore saved results only; pending/running imported entries become cancelled. Batch envelopes are Zod validated, preserve local canonical graph invariants and are bounded to 20 items, 5,000 operators and 5 MiB. Selected SQL is limited to 1 MiB.

## SQL Server

Typed profiles use the same SecretStorage boundary. SQL Server uses a dedicated Tedious connection with 5-second connect and 10-second request timeouts. SHOWPLAN_XML ON and OFF are separate batches; failures never trigger ordinary execution or retries of submitted SQL. Query validation masks strings, bracketed identifiers and nested comments before rejecting Showplan-setting changes, dynamic execution, DDL and SQLCMD controls. SQL Server does not use the PostgreSQL read-only transaction path. Compilation is not an unconditional sandbox: use least-privilege roles. Imported XML rejects DTD/entity declarations and is size/depth bounded before graph rendering.

## AI Assistance

The explicit AI action is the only query/plan upload path. API-key and model controls live under AI Assistance. Keys stay in SecretStorage and host-side Authorization headers; webview requests carry only validated plan/operator IDs, context and optional SQL for imported plans. The host resolves IDs against its active plans. No endpoint is configurable and redirects are rejected. Provider error bodies are not surfaced because they may echo submitted data. Metadata containing connection labels, original batch SQL and duplicate native XML is excluded. Advice does not execute SQL, use tools, alter plans or enter exports. AI response messages are ephemeral and tied to request, plan and operator IDs. The webview renders them as React text, never HTML. Input/output limits, timeouts and cancellation bound requests. `store:false` disables response storage; it is not a promise of zero provider retention.

## Explicit actual execution - 0.6

User-authorized actual runs are a separate path from estimates and AI. Host-side bindings are registered only for live estimates and include a snapshot of the originating profile. Webview requests contain IDs only, never SQL or connection overrides. Execution rechecks workspace trust, current-plan identity and unchanged profile configuration before and after confirmation. Both SELECT and INSERT show a modal with the exact statement and target. Only one pending/active run is allowed; no retries occur. Imports reset all bindings. Stored/exported capability flags are never sufficient authorization.

PostgreSQL executes EXPLAIN ANALYZE with buffers in an explicit transaction, 30-second statement and 5-second lock limits, COMMIT on success and rollback on failure. SQL Server uses STATISTICS XML and autocommit with a 30-second request timeout. Normal rowsets are discarded by column metadata rather than buffered or exported. Driver/session errors or plan-parsing failures can occur after data changes; messages state uncertainty instead of claiming rollback. Cancellation closes the connection but cannot undo committed changes or guarantee cancellation of external effects. Actual plan output is bounded, validated, rendered as text and exported separately only on request. SQL Server original batch context is restricted to required leading literal DECLARE statements, never previous query execution.
